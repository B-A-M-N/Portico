2. **Mutation and durable-state safety** (Findings 2, 5, 6, 12)

## Cross-package dependencies

- Work package 1 must land before work package 3 because terminal verification (finding 8) and repair planning (finding 3) need the `OriginRuntime` projection and causal ordering.
- Work package 2 must land before work package 3 because plan/apply idempotency (finding 12) and shutdown mutation gating (finding 5) affect how `ApplyPlan` and verification observe state.
- Work package 1 must land before work package 4 because environment filtering (finding 10) and process-group management (finding 16) are both origin/process concerns.
- Work package 2 idempotency schema must land before or with work package 5 because event-driven reconciliation (finding 18) relies on durable plan/operation identity.

## Package 1 — Origin lifecycle and ownership

### Invariant
An owned origin process started by Portico must survive the completion of the open/repair operation that started it, and must remain alive until a reviewed close/delete step, supervisor shutdown policy, origin restart, or process failure. Subprocesses must not outlive the origin. The runtime model must represent origin health so observation, reconciliation, repair, and diagnostics can act on it.

### Interface changes
- `internal/core/runtime.go`: add `OriginRuntime` struct (Ownership, URL, Status, PID, StartTime, Executable, CommandHash, LastError).
- `internal/core/runtime.go`: add `OriginStatus` enum (`OriginStatusRunning`, `OriginStatusStopped`, `OriginStatusCrashed`, `OriginStatusUnknown`).
- `internal/origin/origin.go`: extend `Origin` interface with `Identity() core.ProcessIdentity` and `ProcessGroupID() int`.
- `internal/origin/manager.go`: add `Observe(connID) OriginRuntime`, `Healthy(connID) bool`, `StopAll` must use fresh bounded context and retain failed entries.
- `internal/controller/controller.go`: `ConnectionRuntime` embeds `OriginRuntime`; `Observe` merges origin observation.
- `internal/supervisor/reconcile.go`: `ReconcileInput` carries `OriginRuntime`; causal order enforced.

### Files to change
- `internal/core/runtime.go` — new types.
- `internal/core/plan.go` — include `ResolvedOriginURL` and `ResolvedOriginOwned` in plan technical parameters if not already present.
- `internal/origin/local_command.go` — remove `exec.CommandContext` for lifetime; store startup cancellation separately; use process group; signal group on stop; record identity.
- `internal/origin/manager.go` — `Start` returns resolved origin runtime; `Observe`/`Healthy`; `StopAll` fixes.
- `internal/origin/builtin_static.go`, `internal/origin/builtin_filebrowser.go` — expose identity/runtime.
- `internal/controller/executor.go` — pass operation context only for startup cancellation; do not pass operation-lifetime context to origin manager.
- `internal/controller/controller.go` — `Observe`, `PlanRepair` include origin state.
- `internal/supervisor/reconcile.go` — origin-aware reconcile decision.
- `internal/diagnostics/engine.go` — probe owned origins, not only existing-service origins.
- `internal/supervisor/startup.go` — shutdown stops origins and connectors together under a coherent policy; use fresh bounded context.

### Schema/migration
- Migration to add `origin_runtime` JSON column to `connection_runtimes` table, or store in existing runtime JSON if schema already supports arbitrary fields.

### Tests
- Command origin remains reachable after open operation terminal success.
- Cancel during readiness kills command and descendants.
- Close stops origin and its process group.
- Failed connector step compensates by stopping origin.
- Killing origin while connector runs degrades runtime; repair contains `start_origin`; public route recovers.

## Package 2 — Mutation and durable-state safety

### Invariant
No operational desired-state change may be committed outside an immutable operation plan. The supervisor must stop accepting new mutations before canceling operations during shutdown. Runtime persistence must never allow a stale projection to overwrite newer state.

### Interface changes
- `internal/ipc/dto.go`: remove `DesiredState` from `UpdateConnectionRequest`; add `UpdateConnectionMetadataRequest` (name-only).
- `internal/ipc/server.go`: PATCH handler rejects `desired_state`; metadata-only updates route through new handler.
- `internal/supervisor/supervisor.go`: `HandleUpdateConnection` rejects operational desired-state mutation; `HandleUpdateConnectionMetadata` allows name edits.
- `internal/supervisor/supervisor.go`: add `mutationGate` (atomic bool); classify IPC handlers read-only vs mutating; mutating handlers check gate.
- `internal/ipc/server.go`: stop accepting new mutation socket connections when gate closes; return typed `503 supervisor_shutting_down`.
- `internal/supervisor/startup.go`: set mutation gate first in shutdown sequence; stop IPC listener before process teardown.
- `internal/supervisor/supervisor.go`: remove blanket `SaveRuntime` loop after reconcile; persist runtime only at mutation sites.
- `internal/store/sqlite.go`: add `runtime_revision` to runtimes and `SaveRuntime` compare-and-swap; or remove generic save path.
- `internal/ipc/dto.go`: add `IdempotencyKey` field/header.
- `internal/store/sqlite.go`: implement `idempotency_keys` operations.
- `internal/controller/controller.go`: enforce one canonical operation per plan; reject duplicate apply for non-repeatable plans.

### Files to change
- `internal/ipc/dto.go`, `internal/ipc/server.go`
- `internal/supervisor/supervisor.go` (handler methods, reconcile loop)
- `internal/supervisor/startup.go`
- `internal/controller/controller.go`
- `internal/store/sqlite.go`

### Schema/migration
- Migration: `ALTER TABLE connection_runtimes ADD COLUMN runtime_revision INTEGER NOT NULL DEFAULT 0`.
- Migration: activate `idempotency_keys` table with payload hash and committed operation/plan IDs.

### Tests
- PATCH with `desired_state` rejected.
- Metadata-only edit does not trigger reconciliation.
- Concurrent create/update/account/apply during shutdown cannot commit after gate.
- Reconcile stale runtime save does not overwrite newer connector-exit state.
- Retried apply with same idempotency key returns same operation; different payload rejected.

## Package 3 — Plan correctness and process identity

### Invariant
Every plan that depends on observed provider state must carry an authoritative observed fingerprint computed at planning time, and terminal verification must compare the post-operation state against the immutable plan's `ExpectedOutcome`. Process adoption must require a complete four-field identity and never signal on a partial or mismatched identity.

### Interface changes
- `internal/controller/controller.go`: `PlanOpen`, `PlanClose`, `PlanRepair`, `PlanDelete` perform exact-ID observation, compute `ObservedConnection.ComputeFingerprint`, store in `OperationPlan.ObservedFingerprint`, recompute plan fingerprint.
- `internal/controller/executor.go`: `verifyOperationOutcome(ctx, plan)` receives full plan; compares `plan.Expected.State`, public/private addresses, managed resources, DNS target, Access protection, origin health.
- `internal/core/plan.go`: add `ExpectedAddressKind` enum (`Exact`, `Generated`, `Absent`); replace placeholder strings.
- `internal/process/identity_linux.go`: `verifyIdentityFields` requires all four fields; return `ErrIdentityPartial` for incomplete identities.
- `internal/process/manager.go`: adoption rejects partial identity and never signals it.

### Files to change
- `internal/controller/controller.go`
- `internal/controller/executor.go`
- `internal/core/plan.go`
- `internal/process/identity_linux.go`
- `internal/process/manager.go`
- `internal/supervisor/startup.go` (reconstruction adoption path)

### Tests
- Normal `PlanOpen` populates `ObservedFingerprint`; changing provider state before apply fails with typed stale-plan error.
- Running connector with dead origin does not commit terminal success.
- PID-only, missing start time, missing executable, missing command hash identities rejected and never signaled.

## Package 4 — Security boundaries

### Invariant
Child processes must receive only an allowlisted subset of the supervisor environment; provider credentials must not cross the process boundary. Command environment values must be references or explicitly non-secret literals, never raw secrets persisted in profiles. Write-enabled file browsers must not be publicly exposed without explicit protection and reviewed confirmation. File-browser roots must be pinned and HTTP serving must have bounded timeouts.

### Interface changes
- ~~New `internal/process/env.go`: `AllowlistedEnv(extra map[string]string) []string`.~~
  **Built under a different name:** `minimalEnv()` in
  `internal/process/manager.go`, applied in `actor.go` when a spec supplies no
  explicit environment. There is no `env.go`.
- `internal/process/actor.go`: connector uses `AllowlistedEnv`.
- `internal/provider/cloudflare/adapter.go`: permanent connector uses allowlist plus `TUNNEL_TOKEN_FILE`.
- `internal/origin/local_command.go`: command origin uses allowlist plus resolved env references.
- `internal/core/connection.go`: replace `Env map[string]string` with `[]EnvironmentValue{Literal *string, SecretRef *SecretReference}`; literals require `NonSecret bool`.
- `internal/credentials/`: add secret reference resolution.
- `internal/supervisor/supervisor.go`: resolve env references at command-origin start time; never serialize resolved values.
- `internal/controller/controller.go`: `PlanWarning` populated for public write-enabled file browser; reject `ProtectionNone` with upload/delete.
- `internal/origin/builtin_filebrowser.go`: CSRF token on forms; require explicit overwrite (`O_EXCL` default); rate-limit mutations; pin root at construction; add HTTP timeouts and header limits; security headers globally.

### Schema/migration
- Migration: transform existing `source.command.env` and `source.mcp.command.env` from `map[string]string` to `[]EnvironmentValue`. Raw values become `SecretRef` with a synthetic key if name looks sensitive, otherwise `Literal` with `NonSecret=false` and flagged for user review.

### Tests
- Sentinel secrets absent from quick connector, permanent connector, and command-origin environments.
- Resolved env values never appear in inspect/snapshot responses.
- Public write-enabled file browser with `ProtectionNone` rejected at plan time.
- CSRF token required for upload/delete.
- Root symlink retarget after construction does not change served directory.

## Package 5 — Reconciliation, provider, legacy, release confidence

### Invariant
Reconciliation must respond to events, not only a periodic timer. The Cloudflare adapter must be tested through the actual client boundary against a fake HTTP transport. Legacy mutation paths must be isolated and clearly warned.

### Interface changes
- `internal/supervisor/supervisor.go`: add coalescing reconciliation queue (`chan core.ConnectionID` + map); trigger from operation terminal, connector events, profile changes, provider/account events, startup.
- `internal/supervisor/supervisor.go`: keep 15-second ticker as backstop only.
- `internal/provider/cloudflare/`: add test-only fake HTTP transport implementing tunnel/DNS/Access contract; add contract tests using real Cloudflare client.
- `cmd/legacy.go`, `cmd/serve.go`: print warning; isolate legacy provider registry from supervisor registry; prevent modification of supervisor-tracked resources.
- README, help, TUI, capability output: align claims with actual support.

### Files to change
- `internal/supervisor/supervisor.go`
- `internal/provider/cloudflare/` test files
- `cmd/legacy.go`, `cmd/serve.go`
- `README.md`, capability/help strings
- `docs/REMAINING_WORK.md`

### Tests
- Operation terminal event schedules reconciliation for the connection.
- Connector exit schedules reconciliation.
- Fake Cloudflare transport covers all listed status/error cases.
- Legacy command warns and cannot mutate supervisor-tracked connection.

## Midpoint replan trigger

After packages 1 and 2, invoke `portico-architect` (MIDPOINT REPLAN) if:
- Origin runtime projection required schema changes that affect plan/operation identity.
- Removing `desired_state` from PATCH forced new IPC DTOs/handlers that change how reconciliation receives desired-state changes.
- Idempotency schema changed the canonical operation-per-plan assumption.
